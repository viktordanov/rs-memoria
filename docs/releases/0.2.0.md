# Release 0.2.0

**Takeaway:** This release has one clean cutover. It does not read version 1 state, and it performs no automatic migration.

## 1. What changed

Four changes matter to an existing project:

1. **Freshness is portable.** Host ignore settings no longer enter the deterministic policy. Two machines with equal selected inputs and equal repository rules now agree on freshness.
2. **State moved.** `.memoria/state.json` is replaced by a generated binary `memoria.lock` beside `memoria.toml`.
3. **Instructions became guidance.** The `documentation.instructions` and `documentation.instruction_files` keys are now `documentation.guidance` and `documentation.guidance_files`.
4. **`init` is a preview.** `memoria init` writes nothing. `memoria init --apply` creates the two committed files, and it requires a root README that you wrote.

### Portable freshness

Before this release, a change to `core.excludesFile`, the XDG fallback, or `.git/info/exclude` changed the policy hash. A rule that matched no project file still made every document pending.

Now Git decides which files are eligible, exactly as before, and the repository's own `.gitignore` files decide the policy. A host rule that removes or exposes a selected file still changes the owning manifest, because that is a real input change.

## 2. Move a project to this release

Do these steps in order. Steps 1 to 3 remove the legacy state. Steps 4 to 7 move the configuration.

1. Copy `.memoria/state.json` to a directory outside the worktree.
2. Compare the copy with the original file, for example with `sha256sum`.
3. After the copy matches, delete `.memoria/state.json`.
4. Change `version = 1` to `version = 2` in `memoria.toml`.
5. Rename `instructions` to `guidance` under `[documentation]`.
6. Rename `instruction_files` to `guidance_files` under `[documentation]`.
7. Invoke `memoria init --apply` to create an empty `memoria.lock`.

CAUTION: An existing unrelated `memoria.lock` is a conflict to resolve by hand. Initialization never overwrites a file because its name matches.

Then add the binary attribute to `.gitattributes` in the project root:

```gitattributes
/memoria.lock binary
```

Git applies the last matching line, so put this rule after any broad `* text` rule.

The new state starts empty, so every document is never-reviewed. Review the documentation again:

1. Invoke `memoria review` to get the due order.
2. Review each boundary through a fresh packet, in that order.
3. Invoke `memoria render` for managed imports before you acknowledge.
4. Acknowledge each completed review through its packet.

At the end of the sweep, invoke `memoria lint`. Then invoke `memoria check`. Then invoke `memoria status`.

An empty `.memoria` directory can be deleted by hand after every writer stops. Memoria does not delete unknown legacy files.

### Diagnostics during the cutover

| Diagnostic | Meaning |
| --- | --- |
| `state_legacy` | Only `.memoria/state.json` exists. Do steps 1 to 3. |
| `state_ambiguous` | Both state files exist. Do steps 1 to 3. |
| `configuration_invalid` with `version 1` | Do steps 4 to 6. |
| `configuration_invalid` naming `documentation.guidance` | Do step 5 or step 6. |

Memoria checks which state files exist before it selects a decoder. It never picks a winner and never treats legacy state as missing.

## 3. New commands

| Command | Purpose |
| --- | --- |
| `memoria init --apply` | Create the two committed files. Plain `init` previews. |
| `memoria guidance [README.md]` | Show the guidance that applies to a boundary. Read-only. |
| `memoria state inspect [--file PATH]` | Decode committed state. Read-only. |
| `memoria status --summary` | Emit bounded counts only. |
| `memoria agent status` and `memoria agent upgrade` | Inspect and replace a managed skill package. |
| `memoria agent hook …` | Install, inspect, or remove a project `Stop` hook. |

Skill installation gained `--scope local|global` and `--replace-existing`. The default scope is local. An older managed package now returns `skill_upgrade_required`, so replacement is always explicit.

## 4. Renamed contracts

| Contract | Version 2 value |
| --- | --- |
| Release version | `0.2.0` |
| Root configuration | `memoria.toml`, `version = 2` |
| Guidance keys | `guidance`, `guidance_files` |
| State | `memoria.lock`, format 2, codecs 0 and 1 |
| Focused packets and CLI JSON | Schema version 2 |
| Tokens | `mrv2.<16 lowercase hexadecimal characters>` |
| Canonical domains | `memoria.policy.v2`, `memoria.inputs.v2`, `memoria.review-token.v2`, `memoria.packet.v2`, `memoria.guidance.v1` |
| Selection tag | `git-worktree-v2` |
| Repository ignore inventory | `repository-ignore-v1` |

Content hashing keeps raw bytes and XXH3-64 with seed 0. The state frame checksum is XXH3-128.

Memoria rejects a version 1 packet before acknowledgement. Capture a fresh packet instead.

## 5. Build and verification

The Linux acceptance workflow runs these checks:

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build --release --locked
./scripts/check-next-change-set.sh --binary ./target/release/memoria --agent-tests simulated
```

The same workflow cross-compiles `aarch64-apple-darwin` and `x86_64-apple-darwin` on Linux and inspects both binaries. A successful cross-build proves build compatibility. It does not prove macOS runtime behavior, locking, or filesystem durability.

Native macOS execution is a manual smoke check outside automated CI. A release report that does not include that check must state `macOS runtime smoke: not run`.

Native client activation is a separate manual test in a disposable project. Simulated hook tests do not establish verified client activation.
