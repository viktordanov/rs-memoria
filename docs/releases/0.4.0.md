# Release 0.4.0

This release makes review changes easier to read and historical evidence easier to trust.
Full review remains the default. Experimental P1 has no completed model-quality evaluation.

## Changed workflow

`memoria review README.md` and `memoria explain README.md` start with changed paths, evidence, scope, and the next action.
Add `--full` for detailed human output.
Save complete acknowledgement transport with `memoria review README.md --format json > /tmp/review.json`.

Read exact saved content with these commands:

```sh
memoria packet view /tmp/review.json --section guidance
memoria packet view /tmp/review.json --section content
memoria packet view /tmp/review.json --section history
```

For one owned input, use `--file PATH` with its exact packet path.
Selections remain tied to the saved snapshot even after live files change.
They cannot replace the canonical packet for acknowledgement.

New acknowledgements record a commit only when its README, owned inputs, and imported export bodies match the acknowledged snapshot.
Dirty acknowledgements remain valid with partial or unavailable historical coverage.
Bounded local lookup can recover later-committed exact bytes without changing earlier review attribution.
Source commits before acknowledgement remain optional.

## Compatibility

Canonical JSON v2 packets, lock schema, default codec, token format, and raw fingerprints remain unchanged.
Existing JSON streams, exit classes, and packet integrity checks remain in force.
No migration, automatic review, source-history storage, or ordinary Markdown export-provider support is added.

Experimental P1 requires explicit owner approval and a trusted prior review.
The reviewer must justify reuse, retrieve relevant context, and use full-review fallback when required.
Model-quality evaluation remains unrun. Smaller output does not establish review correctness or model-token savings.
The [method and results](../development/review-context.md) record the five-family comparison and its limitations.

## Upgrade and validation

Update the binary through the existing Homebrew or AUR channel.
For an existing local Codex skill installation, invoke `memoria agent upgrade --target codex`.
For Claude, substitute `--target claude`.
Use `--scope global` only for an existing global installation.
A modified installed skill causes a conflict and remains preserved.

The release uses Linux acceptance and the existing Linux-hosted macOS cross-build workflow.
Native macOS runtime smoke, native Homebrew installation, and live client activation remain manual checks.
The published release handoff records completed validation and any unrun package checks.
