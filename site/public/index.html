Never ship stale docs again.

Memoria is CI for your docs. When the code changes, it tells you which documents need another look and shows you what changed. memoria check fails the build until someone has reviewed them.

You and your agents still write and judge every word. Memoria records each review against the exact code the reviewer saw.

Which documents an edit makes pending

      
Each README covers its own folder and everything below it. Edit auth/login.rs, and what goes pending depends on what the root README says about auth/.

    

    

      
1 · says nothing
        
The root still covers auth/, so both are reviewed.


./├─ README.md     pending├─ app.rs└─ auth/   ├─ README.md  pending   └─ login.rs   edited

      

      
2 · links auth/
        
The link hands auth/ to its own README.


./├─ README.md     current├─ app.rs└─ auth/   ├─ README.md  pending   └─ login.rs   edited

      

      
3 · imports a summary
        
The root waits for the summary it imports.


./├─ README.md     waits  ◂─┐├─ app.rs                 │└─ auth/                  │   ├─ README.md  pending ─┘   └─ login.rs   edited

      

    

    
    
      
  • Every README.md is tracked. Other Markdown files join with a marker: an export, an import, or a section. A link alone never tracks a file.
    • 
      
  • A link is a handoff. Remove it later, and the root becomes pending again.
    • 
      
  • Imports carry freshness. They are the only edges between documents, and they set the review order.
    • 
    

  


  

    

      
How Memoria tracks a document

      
Folders decide what a document covers. Markers, plain HTML comments, add the rest. Memoria never needs anything else in your Markdown.

    

    
src/auth/README.md
1# Authtracked · covers src/auth/ and below
2
3<!-- memoria:export id="summary" -->export · a summary others import
4Auth signs users in with a password or a passkey.
5<!-- /memoria:export -->
6
7<!-- memoria:section id="sessions" files="src/auth/**" -->section · changes in src/auth/** start here
8## Sessions
9A session lasts 15 minutes, then the user signs in again.
10<!-- /memoria:section -->

    
every change then runs the same loop

    

      
login.rs changesgit commit
─▸
      
README pendingmemoria status
─▸
      
read the diffmemoria review
─▸
      
fix the READMEyou or your agent
─▸
      
README currentmemoria ack

      
◂──── the next change starts it again ─────

    

    
The ack is bound to one saved snapshot. If anything changed after the review was saved, Memoria rejects the ack instead of approving inputs nobody read. A passing memoria check means every document matches its last review. It does not claim the prose is correct.

  




    

      
Say it once, reuse it everywhere

      
Stop pasting the same paragraph into five files. Export it from one document, import it where it belongs, and memoria render keeps every copy identical.

    

    

      
auth/README.md · provider

<!-- memoria:export id="summary" -->Auth signs users in with a password or a passkey.<!-- /memoria:export -->

      
memoria render

      
README.md · consumer

<!-- memoria:import src="auth/README.md#summary" -->Auth signs users in with a password or a passkey.<!-- /memoria:import -->

    

    
    
      
  • The provider is reviewed first. The consumer waits, so it never reviews text from an unfinished dependency.
    • 
      
  • Only inside import blocks. Render refreshes the managed copies and touches nothing else.
    • 
      
  • One edit, every copy. Change the summary in one place, and each document that imports it is reviewed in order.
    • 
    

  


  

    

      
Tell reviewers what good looks like

      
Write your documentation rules once. Every review names them, and memoria guidance prints them for any document.

    

    

      
memoria.toml · project guidance
[documentation]
guidance = [
  "Explain the operational workflow before implementation details.",
]
guidance_files = ["docs/writing-guidance.md"]

      
AGENTS.md · section guide
<!-- memoria:section id="boundaries"
     guidance="docs/templates/agent-rules.md" -->
## Boundaries
…
<!-- /memoria:section -->

    

    
terminal
$ memoria guidance src/README.md   # the rules for one document
$ memoria guidance --changed       # reviewed documents that saw older wording

    
    
      
  • Advisory, never a trigger. Guidance never selects files and never makes a document pending on its own.
    • 
      
  • A changed rule is reported, not enforced. The review plan shows one assessment item, and memoria check still passes. You decide what needs fresh eyes.
    • 
      
  • Section guides reach only what names them. Project guidance still wins a conflict.
    • 
    

  


  

    

      
Plug into your agent and your CI

      
Three optional integrations. Each one is local and reversible, and none of them reviews a document for you.

    

    

      
agent skill

memoria agent install --target claude
.claude/
└─ skills/
   └─ memoria/

        
The full review procedure, as a skill for Claude Code or Codex.

      
stop hook

memoria agent hook install --target claude
agent stops
└─ 1 document needs review
   → memoria review

        
Reports pending work when the agent stops. It never continues the turn.

      
github check

memoria integrations github install
.github/workflows/
└─ memoria.yml
   runs memoria check

        
Fails the build while a review is pending, with a verified Memoria on the runner.

    

  


  

    

      
What you can use it for

      
Six reasons people reach for it, from one stale file to a gated merge.

    

    

      
Find every explanation a feature change touchesEach document whose scope holds a changed file goes pending, in review order.

      
Block a merge until the docs are reviewedmemoria check fails in CI while a review is pending.

      
Hand an agent one bounded reviewOne artifact holds what changed, what to read, and which guidance applies.

Repeat one summary in several docsmemoria render copies an export into each import, and the provider is reviewed first.

What Memoria never does

      
It proves that a review happened. It never writes the prose or grades it.

    

    

      
writes prose
Only memoria render changes document text, and only inside import blocks you declare.

      
judges prose
Whether an explanation is good or true is for a person or an agent to decide.

      
picks your topics
What each document covers is your choice. Memoria works with the one you make.

    

  


  

    

      
Onboard your agent

      
Tell your agent to run memoria onboard. It explains Memoria, reads where your project stands, and names the next command. Nothing to install.

    

    

      tell your agent
      
Run `memoria onboard` (the Memoria CLI) and follow the next step it gives.

    

    
terminal
$ memoria onboard
Memoria 0.9.2 — CI for your docs

When code changes, Memoria marks the documents that explain it as pending and
shows exactly what changed. `memoria check` fails your build until someone has
reviewed them. You and your agents write every word; Memoria never edits prose.

How it works
  1. Code changes, and every document that covers the changed file becomes pending.
  2. `memoria review` shows what changed and what the review must read.
  3. You or an agent update the document. `memoria ack` records the review.
  4. `memoria check` in CI passes only when no document is pending.
